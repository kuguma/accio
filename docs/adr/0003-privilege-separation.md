# ADR 0003: 権限分離（昇格インデクサと非昇格 UI）

- Status: Agent Working Decision (AWD)
- 関連: [[0001-indexing-by-raw-mft-and-usn]]

## 背景

生ボリューム読み取りと USN ジャーナルは管理者権限を要する。現在は accio.exe 全体が自己昇格する。
Everything は「Everything Service」（SYSTEM で動く小さなサービス）が名前情報だけを非昇格の UI に渡す構成を持ち、
これにより UI が昇格せずに済む（ドラッグ＆ドロップやマップドドライブの扱いが昇格プロセスと非昇格アプリで食い違う問題も避けられる）。

現状の accio には非昇格の読み取り専用モード（`ACCIO_NO_ELEVATE=1`: 保存済み索引のみ、更新なし）があるだけで、
非昇格のまま常時更新を受けることはできない。

## 提案

1. `accio-indexer`（昇格、または Windows サービス）: ボリューム検出・MFT スキャン・USN 追従・索引の永続化・名前順の順列を担当し、
   名前付きパイプで (a) 検索要求に応答する、(b) 索引ファイルの更新通知を流す。
2. `accio`（非昇格 UI）: 起動時に保存済み索引を読み込み、パイプ経由でインデクサに接続できれば差分（USN 適用済みのバッチ）を受け取って自分の索引に適用する。
   インデクサが居なければ現状どおり自己昇格して単体で動く。
3. 差分の形式は `UsnEvent` と `MftEntry`（サイズ・日付込み）の列。UI 側の適用は既存の `accio_index::update::apply` に `RecordSource` を差し替えて使う。

## 代替案（IPC v3 を再利用する）

IPC v3（Everything 1.5 SDK3 互換の名前付きパイプ）が実装済みなので、「昇格した accio を `-startup` でインデクサとして常駐させ、
非昇格の accio UI はパイプ経由の検索結果（プロパティ付き）だけを表示する」構成が、新しいプロトコルを作らずに成立する。
UI 側は索引を持たないため表示用のデータ経路（結果行のプロパティ、容量ビューのフォルダサイズ）を IPC v3 の SEARCH/GET_FOLDER_SIZE で賄う必要がある。
通知（結果変更）は WAIT_FOR_RESULT_CHANGE でポーリングできる。

## 採用した実装（ファイル追従方式）

- `accio -indexer`（昇格、ウィンドウなし）: ボリューム検出・MFT スキャン・USN 追従を行い、変更が落ち着いてから 8 秒で索引ファイルを保存する。フォルダ索引も再走査のたびに保存する。IPC v1/v2/v3・HTTP・ETP はインデクサが提供する（IPC のインスタンス名は `accio-indexer`）。
- `accio`（非昇格 UI、accio.ini の `use_indexer=1`）: 昇格せず、保存済み索引を読み込み、データディレクトリの `*.accio` の更新を 2 秒間隔で監視して差し替える。F5 でインデクサに保存を要求する（WM_USER SAVE_DB）。
- ログオン時の自動起動は設定画面からタスクスケジューラ（`/RL HIGHEST /SC ONLOGON`）に登録する。UAC はその登録時の一度だけ。
- 検証: 非昇格のインデクサ（フォルダ索引）と追従 UI で、ファイル作成から 4 秒で UI の検索に現れることを確認。

反映の遅延は「変更が落ち着いてから約 10 秒」。Everything Service のような即時反映ではないが、プロトコルを増やさずに済み、索引の所有者がインデクサだけになる。

## 未決

- サービス化（SCM 登録、SYSTEM での実行、UI セッションとの分離）か、ログオン時に昇格起動するヘルパープロセスか。
  Everything Service は前者。UAC プロンプトを一度だけにするには前者が必要。
- 保存済み索引ファイルを両プロセスで共有するときの排他（インデクサが書き、UI が読む）。
