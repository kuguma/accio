# 起動時と常駐中の処理

Status: Agent Working Decision

索引の保守処理は、他のアプリケーションに CPU とディスクの利用を譲る。検索と画面操作は通常の優先度を維持する。

読み込み、保存、名前順の計算、全走査には、最大 2 スレッドの専用プールを使う。ボリュームをまたぐ重い処理は順番に実行する。MFT の読み取りは 1 スレッドで、読み取り単位は 4 MiB とする。これらのスレッドと、ボリューム・フォルダの監視スレッドは Windows のスレッド単位のバックグラウンドモードに入る。

USN の読み取りバッファは 256 KiB とし、20 ms 以上処理したらバッチの間で待機を挟む。ディスク要求自体が 20 ms 以内に終わることを保証する値ではない。

検索には通常優先度の Rayon プールを使う。画面を隠すと画面用の検索を取り消し、再表示時に検索し直す。非表示中も外部からの IPC 検索を受け付ける。

トレイと IPC からの終了は、設定と索引を保存する通常の終了経路にまとめる。ネイティブの終了イベントに続けて、キューを経由しない描画通知を送ることで、ウィンドウを表示せずに終了を処理する。通知用スレッドを使い、トレイのコールバック内で画面処理に再入しないようにする。画面側は通知用スレッドを待たない。索引の更新だけでは非表示画面の描画を強制しない。

`probe-resident` タスクで、起動時の CPU 使用量、待機中の CPU と I/O、スレッドの優先度、IPC 検索時間、非表示中の終了、セッション保存を検証する。保存済み索引の一時コピーを使い、検証後に自分が起動したプロセスを停止する。実際の USN 更新には管理者権限の端末が必要となる。音飛びは、問題の起きたオーディオデバイスで Musa を再生して確認する。
